# WinWin DevOps test task

Nginx reverse proxy (:8080) in front of a tiny Python app, with request-id passthrough
and rate limiting (10 r/s, burst 5 -> HTTP 429).

## Prerequisites
- Docker Engine with Compose v2 (`docker compose`), `make`, `curl`, `jq`

## Run
```bash
cp .env.example .env     # set ENV_NAME (default: local)
make up                  # build + start, waits until both containers are healthy
make test                # healthz, request-id and flood checks
make logs
make down                # removes containers and network
```

## Expected output
```bash
$ curl -s http://localhost:8080/healthz
{"status":"ok","service":"app","env":"local"}
```
Flood test (`make test`) prints a mix of `200` and `429`.

## Design notes
- Only the proxy publishes a port (8080); the app is reachable only via the `appnet` network.
- `X-Request-ID` is taken from the client or generated by nginx, forwarded to the app
  and returned in the response; it appears in nginx and app logs.
- Rate limit is per client IP: `limit_req_zone` 10r/s, burst=5 (remove burst for a strict limit).
- App runs as non-root, read-only FS, all capabilities dropped.
- Healthchecks use 127.0.0.1 (avoids IPv6 `localhost` resolution issues in Alpine).
